# 验证范围及试点差距

| 范围 | 可重复验证入口 | 验证边界 |
| --- | --- | --- |
| 资产、CMDB、授权、目标控制、并发和证据 | Maven verify，ControlPlaneTest | H2 和 MySQL 8。覆盖重复决策、过期、撤销、跨用户访问、版本冲突、共享快照、应急代次、临时源码和引用失效 |
| Java 8、11、17、21、25 目标 | GitHub Actions 的 Attach to Java 任务 | Linux x86_64、Corretto 和指定 Arthas 4.3.5。运行真实附着、明确加载器的类和方法诊断、无命中中断、端点关闭，确认业务 JVM 存活 |
| 双向认证及本地回收 | gateway-smoke.py | 多个客户端证书、代理身份隔离、SQLite 回执与真实样例进程。Java 17 任务实际暂停网关后等待离线回收、恢复网关并核对审计 |
| 工作台和认证 | console-smoke.py、sso-smoke.py | Chromium 打开真实平台页面，从申请、审批到显示诊断结果；临时签名密钥验证受众、过期、主体映射和权限 |
| 资源成本 | fixture-performance.py | 一次 Java 17 合成测量中，Arthas 已加载时 CPU 为单核 0.87%，周期快照时为 3.93%。基线与采样阶段分别有 5 和 6 个有效交易批次，每 16 次交易计算一次 P95，批次 P95 最大值为 38.15 ms 和 37.42 ms。三次快照的最近秩 P95 为 5.26 秒。这组数据不覆盖真实应用启动时延、业务高峰并发或首次介质分发 |
| 现场留存及剖析 | fixture-experiments.py | Java 17 独立合成样例生成并删除一次 wall 剖析文件，留存并删除一次调用记录。原始对象、重放和性能剖析没有开放为生产 API |

## 现场验收输入

- 应用、网区、服务账户、完整 JDK 厂商及更新号、实际工作负载、允许观测的方法清单和介质审批记录。
- 身份签发者和公钥轮换机制，审批事件来源、CMDB 版本语义、告警/APM 跳转和 ITSM 幂等接收契约。
- 容器 cgroup 和命名空间可见性、Pod UID 注入、重建与删除演练。跨网区实测需提供两条可独立故障的网关链路和测试数据库 HA 环境。
- 生产侧的性能基线、各档案开关、配额、证据保留策略、故障应急责任人及准入签核。当前使用测试数据和本地证书，正式系统联调与生产准入需独立验收。

## 已知实现边界

代理为 Python 3.11+，中心组件为 Java 17，目标 JVM 独立支持已验证的 Java 版本。网关使用经双向 TLS 保护的 HTTPS 拉取。工作台采用随平台打包的原生网页。参考设计中的 Java 代理、Vue 3 前端、WebSocket 长连接和实时外部系统连接均未作为当前实现交付。代码预览以方法或类为范围限长展示。原生 Trace 可能只返回线程根节点，此时面板显示部分结果。已锁定存量目标但无法验证端点归属的任务可能需要现场人工核对。
